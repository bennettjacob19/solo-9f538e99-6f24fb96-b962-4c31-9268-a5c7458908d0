# 遥测 UDP 代理（接收器 A/B 切换 + 上行抓包对账）

遥测终端经 UDP 代理把短报文发给接收器，值班员在网页上：

1. 切换接收器 A/B（已建立的会话不受影响，回包不会送错设备）；
2. 对活动会话启动**最长 30 秒的上行抓包**，核查报文是否完整到达接收器，
   并下载两份 Wireshark 可直接打开的 PCAP。

## 组成

| 组件 | 说明 |
|---|---|
| `proxy/` | asyncio UDP 代理 + Flask 操作网页 + SQLite 持久化 + 抓包对账 |
| `receiver/` | 本地接收器，原样回显报文，可延迟回包；含独立抓包记录与 HTTP 控制接口 |
| `common/pcaputil.py` | 纯标准库 PCAP 写入器（含真实 IPv4/UDP 校验和，Wireshark 可打开） |
| `docker-compose.yml` | 一键启动代理 + 接收器 A + 接收器 B |
| `scripts/verify_local.py` | 无 Docker 环境下的端到端行为验证（56 项检查） |
| `tools/flask_shim/` | 仅供本机无 Flask 时验证用的最小兼容垫片，不进入镜像 |

## 启动

```bash
docker compose up --build
```

- 操作网页：http://localhost:8080
- 遥测终端发送地址：`UDP <宿主机>:9000`

## 上行抓包对账（核心证据规则）

### 两个相互独立的证据点

| 侧 | 记录内容 | 记录时机 |
|---|---|---|
| 代理侧 | 会话上游套接字**实际发出**的 UDP 原文 | 仅在 `sendto` 成功之后记录 |
| 接收器侧 | 接收器 **实际收到**的原文，按本会话代理上游端口过滤 | 接收器独立进程独立落盘 |

### 启动与停止顺序（保证两侧窗口可对账）

1. 代理先调用接收器 HTTP 控制接口启动接收器侧记录，并**等待确认**；
2. 接收器确认后，代理侧才布防开始记录 —— 因此代理记录的每一条都落在
   接收器窗口之内，**只有两侧都确认启动之后的报文才参与对账**；
3. 停止时代理先撤防冻结，再通知接收器在一个短宽限期（`CAPTURE_STOP_GRACE`，
   默认 0.25 s）后冻结，保证代理冻结前已发出的在途报文仍进入接收器文件。

### 对账口径

- 以报文 `SHA-256` 摘要做**多重集**核对，页面按“报文摘要 + 出现次数”展示：
  - **已证实到达**：同摘要两侧次数取小；
  - **未证实**：代理次数减接收器次数（代理有、接收器无）；
  - **漏记**：接收器次数减代理次数（接收器有、代理无，见于停止/收包交错等边界）。
- **同文重发按次数核对**：同一份收包不能把多次重发算作全部到达。
- 页面三列数量，而不是简单“有/无”。

### 证据不完整的判定（此时只报告未证实，**绝不断言丢包**）

- 任一侧启动/停止/取结果时**失联**；
- 任一侧 PCAP 达到 **1 MiB 硬上限**（抓满只停止记录，转发与回显完全不受影响）；
- 代理记录器初始化失败或接收器 PCAP 取回失败。

页面与详情页会显式提示“证据不完整 —— 不得据此断言丢包”。

### 会话关闭、端口复用与停止/收包交错

- 抓包期间会话关闭（空闲过期等）：其上游端口被**冻结到抓包结束**，不会被
  新会话复用，因此两份 PCAP 只包含本次会话、本窗口的报文；
- 抓包在窗口结束或会话关闭后立即冻结，结果（两份 PCAP + 对账 JSON）落盘，
  **已下载的结果永久不变**，代理重启后仍可下载且字节一致；
- 停止与收包交错：撤防后的报文不再入文件；接收器宽限期内的在途报文仍入文件，
  冻结后的新报文不影响已冻结结果。

### PCAP 格式

- 标准 libpcap（`LINKTYPE_ETHERNET`），自行拼装以太网/IPv4/UDP 头并填写真实
  校验和，Wireshark/tcpdump 可直接打开；
- 每侧文件含 24 字节全局头，每条记录含 16 字节记录头 + 完整帧；
- 帧四元组固定为本次抓包的（代理上游 IP:端口 → 接收器 IP:端口），可逐条核对。

## 转发行为规则

- **会话**：按客户端 `IP:端口` 建立，空闲 5 秒（`SESSION_IDLE_TIMEOUT`）无收发即过期。
- **建会话时固定接收器**：会话期间的一切报文都发往建会话那一刻的目标接收器；
  网页切换 A/B 只影响之后新建的会话，旧会话继续走原接收器直到过期。
- **原样透传**：报文与回包内容不做任何修改；抓包逻辑任何异常都不影响转发。
- **回包不错投**：每个会话使用一条独立的、已 connect 到其接收器的上游 UDP
  套接字（独立本地端口），只有该会话对应接收器的回包会被送回该客户端。
- **迟到回包**：会话过期即关闭其上游端口，端口进入冷却期
  （`UPSTREAM_PORT_COOLDOWN`，默认 30 秒，应大于最大回包延迟）不再分配；
  因此相同 `IP:端口` 重建的新会话也不可能收到旧会话迟到的回包。
- **切换可靠性**：切换先写 SQLite 再生效，保存失败保留原目标并在网页报错。
- **重启**：目标接收器与已冻结抓包结果保存在 SQLite/卷中，重启后保留；
  会话全在内存，重启即清空。

## 接收器延迟回包与测试丢包

- 环境变量 `REPLY_DELAY`：该接收器所有回包的默认延迟秒数。
- 报文级覆盖：报文以 `DELAY:<秒>:` 开头时按该值延迟（回包仍是完整原始报文）。
- `DROP_CONTAINS`（可选，测试用）：逗号分隔的字节子串，命中即整包丢弃
  （不回显、不入 PCAP，但计入接收器“窗口内收报/测试丢弃”统计），
  用于在证据完整的前提下现场观察“未证实”计数。

## 配置（环境变量）

### 代理（proxy）

| 变量 | 默认 | 说明 |
|---|---|---|
| `UDP_LISTEN_PORT` | `9000` | 代理对终端的 UDP 监听端口 |
| `HTTP_PORT` | `8080` | 操作网页端口 |
| `SESSION_IDLE_TIMEOUT` | `5` | 会话空闲超时（秒） |
| `RECEIVER_A_HOST/PORT`、`RECEIVER_B_HOST/PORT` | 见 compose | 接收器 UDP 地址 |
| `RECEIVER_A_CONTROL_URL`、`RECEIVER_B_CONTROL_URL` | 本机 9101/9102 | 接收器抓包控制 HTTP 地址 |
| `DB_PATH` | `/data/proxy.db` | SQLite 路径（目标持久化） |
| `CAPTURE_DIR` | `<app>/captures` | 抓包结果目录（两份 PCAP + 对账 JSON） |
| `CAP_MAX_SECONDS` | `30` | 单次抓包窗口上限（秒） |
| `CAP_MAX_BYTES` | `1048576` | 每侧 PCAP 硬上限（1 MiB） |
| `CAPTURE_STOP_GRACE` | `0.25` | 接收器停止宽限（秒），容纳在途报文 |
| `RECEIVER_RETRY_WINDOW` | `10` | 接收器失联时的启动重试窗口（秒） |
| `UPSTREAM_PORT_MIN/MAX` | `20000/29999` | 上游本地端口池 |
| `UPSTREAM_PORT_COOLDOWN` | `30` | 上游端口关闭后的冷却秒数 |

### 接收器（receiver）

| 变量 | 默认 | 说明 |
|---|---|---|
| `LISTEN_PORT` | `9001` | UDP 监听端口 |
| `CONTROL_PORT` | `9101` / `9102` | 抓包控制 HTTP 端口（仅 compose 内网） |
| `REPLY_DELAY` | `0` | 默认回包延迟（秒） |
| `CAPTURE_DIR` | `/tmp/telemetry-captures` | 接收器侧抓包暂存目录 |
| `CAP_MAX_BYTES` | `1048576` | 单次抓包字节上限（由代理下发覆盖） |
| `DROP_CONTAINS` | 空 | 测试用丢包子串 |

## 本地验证（无需 Docker）

本机有 Flask 时：

```bash
pip install flask
python3 -I scripts/verify_local.py
```

本机无 Flask 时，脚本会自动使用 `tools/flask_shim` 最小垫片（仅实现验证所需
子集；镜像内始终通过 `requirements.txt` 安装真正的 Flask）：

```bash
python3 -I scripts/verify_local.py
```

验证覆盖（56 项）：原样透传（含二进制、校验和正确的 PCAP）、切换后旧会话走原
接收器、过期重建走新接收器、迟到回包不投递、网页试传、重启保留目标并清空会话、
保存失败保留原目标；抓包 happy path、同文重发按次数核对、真实未到达的未证实
统计、抓包中会话关闭与端口冻结、停止宽限在途报文、停止/收包交错结果不可变、
接收器失联标记证据不完整且不断言丢包、1 MiB 抓满只漏记不影响转发、重启后
已下载 PCAP 字节不变。
